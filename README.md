# Бронирование переговорной

SPA для бронирования одной переговорной комнаты (рабочий день 09:00–18:00): выбор даты, таймлайн броней, создание, редактирование (в том числе перенос на другую дату) и удаление. React 19 + TypeScript, mock API на MSW.

**Демо:** https://meeting-room-booking-interface.vercel.app (mock-сервер работает прямо в браузере, данные хранятся в `localStorage`).

## Запуск

Нужен Node ≥ 22.12.

```bash
npm install
npm run dev            # http://localhost:5173, mock API в браузере (MSW)
npm run build && npm run preview   # продакшен-сборка, http://localhost:4173
```

| Команда                              | Что делает                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| `npm test`                           | Vitest: unit (домен, часы, API-клиент), handlers mock-сервера, интеграционные сценарии UI |
| `npm run lint` / `npm run typecheck` | oxlint / `tsc -b`                                                                         |
| `npm run mock:server`                | тот же mock API как Node HTTP-сервер (`:3001`) — для curl                                 |
| `npm run test:api`                   | проверка контракта через curl + jq, кейсы A01–A33                                         |
| `npm run test:e2e`                   | Playwright (`--grep @smoke` — только дымовые)                                             |
| `npm run qa`                         | интерактивный проход сценариев E01–E64 со скриншотами (`QA_VIEWPORT=mobile` — мобильный)  |

Браузеры для e2e: `npx playwright install chromium`. Против деплоя: `E2E_BASE_URL=https://… npx playwright test --grep @smoke`.

## Архитектура

```
src/
  domain/    чистые правила (время, пересечения, валидация) — без React и без Date.now()
  shared/    clock, storage, хуки useNow / useSelectedDate, базовые ui
  api/       ApiError, http-клиент (fetch + zod), BookingsApi, TanStack Query хуки
  features/booking/   страница, таймлайн, форма, диалоги, тексты
  dev/       панель симуляции (только при VITE_USE_MOCKS)
  mocks/     MSW handlers, репозиторий, симуляция, Node-сервер (UI их не импортирует — проверяет oxlint)
docs/        SPEC.md, TASKS.md, REVIEW.md, qa/REPORT.md
```

Зависимости: `domain` ← `shared` ← `api` ← `features` ← `app`; `mocks` зависит от `domain` и `shared`. Правила бизнес-логики написаны один раз (`domain/rules.ts`) и используются и формой, и mock-сервером. Переход на реальный backend: `VITE_USE_MOCKS=false` и `VITE_API_BASE_URL`, код UI не меняется.

## Принятые решения

Согласованные с заказчиком (шаг 15 минут, прошедшие и идущие брони только для чтения, перенос даты разрешён, локальная таймзона, три способа получить 409 и т. д.) — в [SPEC §1.1](docs/SPEC.md), решения исполнителя — в §1.2. Ревью спецификации — [REVIEW.md](docs/REVIEW.md).

Решения при реализации (мелкие, не меняющие согласованного поведения):

- **oxlint вместо ESLint** (его ставит шаблон Vite 8); граница «UI не импортирует mocks» — правило `no-restricted-imports`.
- **Валидация формы выводится при рендере**, а не хранится в состоянии RHF: единая функция `validateForm` (zod для формата и названия + правила домена) считается от текущих значений, броней своей даты, `now` и серверных ошибок. Поэтому после рефетча или тика часов ошибки пересчитываются сами, а серверные `fieldErrors` не стираются (отдельное состояние). Ошибки показываются сразу, без ожидания `touched`: поля — селекты и дата, ошибиться «случайно» нельзя, а скрывать ошибку от пользователя, чья бронь стала недоступной, вредно.
- **Дата в URL** меняется через `replaceState` (история не засоряется), невалидный `?date=` заменяется сегодняшней датой.
- **Форма создания ждёт данных своей даты**, чтобы выбрать первое доступное начало; при ошибке загрузки — сообщение и «Повторить», отправка заблокирована.
- **Сообщение о 409 и фокус «сразу»**: для этого хуки мутаций принимают `onError`, который вызывается до завершения рефетча (иначе fieldset был бы ещё `disabled`).
- **Часы**: `KeyValueStorage` и override времени вынесены в `shared/`, потому что UI и mock-handlers читают один ключ `localStorage`. `GET /api/__dev/state` отдаёт `now` = закреплённое время или `null`.
- **Отличия от спецификации** (найдены при реализации, исправлены в SPEC, см. REVIEW → «Правки при реализации»): в `msw@3` опция называется `onUnhandledFrame`; событие `visibilitychange` в E54 должно быть с `bubbles: true`, иначе TanStack Query его не видит.
- **Node-сервер**: `@msw/serve` в standalone-режиме превращает `HttpResponse.error()` в 500; поэтому `node-server.ts` перехватывает статус 0 и обрывает сокет (curl: код 52) — express-вариант не понадобился.
- Версии: zod 3.25 (стандартный API, совместим с `@hookform/resolvers`), Vite 8, TypeScript 6, Vitest 5.
- E2E и интерактивный проход используют **один набор сценариев** (`scripts/qa/groups`, подключаются в `e2e/*.spec.ts`). Проект `mobile-chromium` задаёт только размер окна Pixel 7 без эмуляции касаний.

## Как воспроизвести 409

1. **Фоновая гонка:** «Панель симуляции» (внизу страницы) → «Вероятность «чужой» брони» 100% → создайте или продлите бронь: сервер вставит «Занято другим сотрудником» и вернёт 409.
2. **Принудительно:** включите «Следующая мутация вернёт 409» и отправьте форму.
3. **Две вкладки:** в панели выключите «Обновлять при возврате на вкладку», откройте приложение во второй вкладке, создайте там бронь на то же время, вернитесь в первую и отправьте форму.

После 409 форма остаётся открытой со всеми значениями, фокус переходит на «Начало», список обновляется, занявшая время бронь подсвечена на таймлайне.

## Дополнения сверх спецификации

По отдельной просьбе добавлены (в SPEC §11 они значились «вне скоупа»):

- **Тёмная тема**: переключатель «Тёмная тема» в шапке, выбор сохраняется в `localStorage`, по умолчанию берётся `prefers-color-scheme`. Реализована переопределением палитры в `index.css` (класс `dark` на `<html>`), axe в тёмной теме — без critical/serious.
- **Drag-and-drop**: бронь можно перетащить мышью по вертикали, время сдвигается с шагом 15 минут (длительность сохраняется). Во время перетаскивания показывается новое время; «занято» или нарушение правил — красная подсветка, при отпускании запрос не отправляется. Esc отменяет. Интерфейс обновляется оптимистично: новое время видно сразу, при ошибке сервера бронь возвращается на место. Блок плавно следует за курсором, пунктирная «тень» показывает целевой слот. Отправляется тот же `PATCH`, что и из формы (серверные правила и 409 работают так же). Идущие и прошедшие брони не перетаскиваются. Касания не обрабатываются (конфликт со скроллом) — на тач-устройствах остаётся форма. Сценарии E66–E73 (в том числе оптимистичное обновление и отсутствие сдвига раскладки при появлении полосы прокрутки).

## Что не сделано / ограничения

- **WebKit не проверялся**: в WSL нет системных библиотек (нужен sudo). Конфигурация `desktop-webkit` для `@smoke` в `playwright.config.ts` есть, но не запускалась. Проверка в Safari не выполнялась.
- Экспорт переписки с AI (SPEC §10, T18) в репозиторий не включён — по решению автора.
- Проверка скринридерами (VoiceOver/NVDA) недоступна — не делалась (SPEC §8).
- Известных открытых багов нет. Найденные баги и исправления — в REPORT.md; после завершения работы приложение проверили четыре независимых агента (ревью кода, критик по SPEC, тестировщик, UX/доступность), все подтверждённые находки исправлены (таблица в REPORT.md). Сознательно не сделаны: разбиение крупных компонентов, предпросмотр слота на таймлайне, перестройка раскладки для устранения прыжков при появлении формы.
- Вне скоупа (SPEC §11): несколько комнат, повторяющиеся брони, синхронизация вкладок в реальном времени, CI.
